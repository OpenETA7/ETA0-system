# 11 月 24 日设计提案：上层理解意图，27B 独立完成一轮

**建议把一次完整的 27B 尝试作为交接边界。** 商用模型在开跑前看初始场景、和用户消除歧义，交付一条完整任务指令以及至多一个有出处的示例。之后 27B 自主观察、规划、调用工具和执行。失败后，上层可以根据结果修改下一轮的输入。主指标是用户请求最终是否完成，同时保留首轮成功率，以看清收益来自哪一环。请求级实现与对照实验入口见[运行说明](request-harness.md)。

## 两组实验支持哪些选择

- 在旧分层实验里，有 50 个初态在四组都正常取得原生评分。原 harness 成功 36 次，Qwen、DeepSeek、Kimi 上层分别成功 16、13、20 次。一个开炉灶案例里，原版 7 个动作成功，Qwen 组经历 21 次上层调用仍超时。那次实验同时改变了任务拆解、监督、示范和预算占用，单项影响仍待消融。[本地归档：旧实验诊断](../outputs/j-1795258253-584889/trajectory-diagnosis.md)
- 当前 27B 单独执行的 200 对里，开放环境进度查询时成功 138/200，关闭时 131/200。33 条转胜轨迹中 24 条实际查询为零。因此新设计可让执行器继续自主选工具，各实验组固定相同的工具提示和权限。开启组 62 条失败都耗尽了底层墙钟；给新系统第二轮后，必须同时给基线相同的重试机会。[本地归档：逐任务配对结果](../outputs/libero40-progress-query/results-zh.md)

## 用户从提出请求到看到结果

| 时机 | 可用证据和决策 | 用户看到什么 |
|---|---|---|
| 开跑前 | 上层读用户原话和带视角标识的初始图。请求清晰可直接沿用原话；只有会改变目标、动作、约束或完成标准的歧义才追问。 | 通常只说一句目标。确需选择时，展示当前图中的两个候选和一个简短问题；用户也可直接点选。 |
| 交给 27B | 保留原话，附可见辨识线索、目标状态及必要约束。示例可为空。交接后冻结本轮输入。 | 一句“我理解的是……”及正在执行状态，界面提供停止入口。 |
| 轮内 | 27B 持有完整目标，可查询环境进度。动作继续经适配器校验，原生成功立即结束。模型提前报完成而环境判负，仍由 27B 在本轮内处理。 | 需要时查看实时画面。用户停止、硬件保护和环境终止直接生效。 |
| 轮后 | 失败时读取终止原因、末帧、最新公开回执及少量关键帧。成功结束；可恢复失败才考虑下一轮。用户停止直接结束本次请求。基础设施故障单列。 | 成功给结果；重试时说明“已经完成什么，这次改什么”。预算用尽则展示最后状态。 |

例如用户说“请拿起桌上的白色魔爪饮料”。初始图能确认对象时，可交付“拿起桌上那罐白色魔爪饮料。它是银白色的圆柱形饮料罐。”品牌、动作和桌上范围都保留。若画面里有两只相同颜色的罐子且商标不可辨，先问“你指靠近盘子的那罐，还是靠近水杯的那罐？”“递给我”“放到盘里”都属于新增目标。视觉描述绑定到采集时的视角；涉及左右时保留用户参照系和相机方向。无需为每种商品维护规则。

## 任务专用 skill 怎样泛化

让上层临时为**当前请求选择示例**，harness 只维护一种通用示例接口。第一版将 skill 定义为可选的上下文示例，由 27B 自己决定是否借鉴。一个库条目包含成功判定来源、演示适用条件、物体与目标关系、相机和控制协议、少量关键帧以及动作产生的可见结果。来源 ID 用于追溯，历史坐标和历史 observation ID 留在示例记录里。

1. 先按相机、末端和控制协议筛选兼容样例，再比较目标关系与操作难点。比如“把碗放进抽屉”优先匹配相同开口和容纳关系，外观相同的碗放上桌面帮助有限。候选质量不够时返回空，由 27B 直接做。任务名称相近只作为检索线索。
2. 上层从一条经过验证的成功轨迹提取“可见线索 → 操作方式 → 可观察结果”，保留必要关键帧和出处，用 27B 原有图文格式放入每轮固定上下文。历史轨迹中未观测到的抓稳、接触和意图保持未知。当前坐标与动作始终由 27B 根据现场重新生成。
3. 上层亲自示范作为单独实验。先在支持复制状态的仿真副本或独立演示场景里，用公开观测和相同动作校验执行完整轨迹；环境判成功才可作为 demo。尝试失败、超时或现场无法复位，就走零样例路径。记录示范用时、成功率和下游净收益。在正式测试初态上预演属于额外一次解题机会，须单列；首版用独立演示场景。
4. 预先冻结演示库和测试划分。使用同任务其他初态的示例与跨任务示例分开报告；验证跨任务泛化时，留出整个任务及近重复场景。刚跑完的 400 条适合诊断；其中的成功样本若进入库，后续用独立测试集评估。

## 整轮失败后怎样调整

首版建议一次请求最多两轮。第二轮保存原始意图，只改有失败证据支持的部分，例如两只罐子辨识混淆就补目标线索，示例的抓取条件与现场不符就撤掉示例。若只是抓取滑脱且语义已经明确，允许原指令再试。目标已部分完成时读取新鲜观测，继续条件和最终目标同时给 27B。

- **面向用户的续做**：沿当前物理状态开启新的 27B 对话。一轮结束只释放该轮推理上下文，环境由外层持有。若目标物体已移走或现场不能恢复，先报告状态并让用户决定。真实机器人只有可验证的传感反馈或用户确认才能据此宣告成功，无法核实时呈现“待确认”。
- **离线比较**：产品续做与从原始快照重新尝试是两种不同实验。对“轮后修订是否有效”，让两个分支从同一失败末态继续，一个沿用原指令、一个仅修订指令或示例。不能忠实恢复模拟器、控制器与夹爪状态时，改用配对的完整两轮运行并注明。所有组固定底层每轮预算、最大轮数与总预算。上层和预演单独计时，用户端到端耗时包含对话、预演和重试。

## 如何落到现有仓库

在单 episode 入口外增加请求级控制器，维护原始意图、用户澄清、轮次、环境生命周期和总预算。开跑时将用户原话、执行指令、可选示例交给 base 循环，沿用历史压缩时保留原始意图和示例边界。轮内以 `hierarchy=None` 调用 `harness.run`；每轮使用新目录，避免把上一次动作当作待重放的动作。把 `eta0_run.py` 的适配器初始化与关闭移到请求级，支持一次 reset 多轮续做。验收时用调用记录验证首个 27B 决策到本轮终止之间的商用 API 调用数为零，包括截断、进度查询和提前 finish 的路径。[单轮执行器](../harness.py) · [LIBERO 入口](../eta0_run.py)

**实施次序建议如下。**

| 阶段 | 对照 | 决策依据 |
|---|---|---|
| 意图改写 | 相同 27B、初态和工具，对比原话与经上层处理后的指令；同时测试清晰指令、品牌别称、重复候选、空间参照。歧义样本预先保存用户真实意图和标准澄清回答。 | 首轮任务成功率、错目标率、改写是否漏掉约束、澄清次数及首动作延迟。分别查看清晰和歧义子集。 |
| 检索示例 | 做“改写开关 × 检索开关”四组；使用同一冻结库，没选中示例也纳入开启组。 | 成功率及逐初态转胜、转败；按库命中、无匹配及留出任务报告。验证干预、比较不同能力上层时固定其余配置。 |
| 轮后修订与上层示范 | 同预算两轮基线对照轮后修订；独立增加“允许上层预演”组，各组核算所有尝试。 | 每请求成功率、首轮成功率、救回的初态、额外时间和商用调用成本。 |

**关于训练回流。** 运行时 ICL 使用冻结权重。当前实验没有训练任何小模型，也不能判断把协作轨迹用于训练会涨点还是掉点。值得关注的风险是：轨迹中的决定依赖上层给过的目标线索或示例，学生训练时看不到同样的上下文，却被要求模仿该动作。当前产品只依赖已有示例库与少量诊断日志。若以后专门研究训练回流，单独立项，用相同训练预算比较原数据和混合数据，检查学生独立执行时在原有任务及留出任务上的表现。

**产品交付。** 人类只需输入目标、回答必要的指代问题并查看结果。给 coding agent 的 README 指令分两层验收：本地离线示例验证安装和工具入口；带真实 27B 服务、仿真依赖和商用凭据的环境再做端到端验收，分别汇报状态。现阶段可复制的部署提示词见[中文 README](../README.zh-CN.md#给-coding-agent-的部署提示词)（[English](../README.md) · [日本語](../README.ja.md)）。
