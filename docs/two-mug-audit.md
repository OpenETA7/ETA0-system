# 两杯分盘的三条漏报

本文记录的是针对既有轨迹的离线诊断。运行时向 27B 提供通用的环境进度查询。下文的交叉支撑检查、抓放次数和等待阈值仅用于分析这批轨迹。[运行时工具协议](executor-led.md)

在原 harness 的 `libero_10 / task 04` 上，三个失败初态都没有保存逐条件回执。本次在本机用原始初态和逐 tick 控制指令重建，三个初态在每个物理动作结束时的正确摆放数都是 **0/2**。额外检查“杯子是否放在另一只盘子上”后，初态 2 在第 34 个动作后满足复核条件，初态 0、1 的证据不足。同任务 50 条官方成功演示在首次原生成功前均未触发这套候选规则。云测保持停止，生产 harness 的触发逻辑和配置均沿用原值。

## 逐条件回执能回答什么

0.3.2 的 `native_goal_conditions_v1` 返回两个具名条件。第一项是白杯在初始左盘，第二项是黄白杯在初始右盘。原生 `on` 同时检查高度次序、实际接触和水平中心距离小于 30 mm。审计取每次原生判定后的回执，并核对查询新增的原生评估调用数为零。为检验错盘，另在本地评测环境读取两项交叉支撑关系，顺序为“白杯在右盘、黄白杯在左盘”。这是额外的模拟器状态访问；0.3.2 的公开完成度接口仅提供目标对应的两项。[语义包与绑定](https://github.com/OpenETA7/OpenETA-Benchmark/blob/c39883cd94c3b413c19e048ab82317fc6e024fa1/src/openeta_bench/data/task_packs/libero/full-v1.json) · [LIBERO 的支撑判定](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/8f1084e3132a39270c3a13ebe37270a43ece2a01/libero/libero/envs/object_states/base_object_states.py#L78-L94)

| 在相同场景里核验的状态 | 正确盘（白、黄白） | 错误盘（白、黄白） |
|---|---|---|
| 官方 demo_0 初始状态 | 0, 0 | 0, 0 |
| 演示中先放好白杯 | 1, 0 | 0, 0 |
| 第 226 帧，两杯都放好 | 1, 1 | 0, 0 |
| 从第 226 帧移高白杯，黄白杯保持原位 | 0, 1 | 0, 0 |
| 从第 226 帧互换两只盘子的位姿，保持两杯原位 | 0, 0 | 1, 1 |

最后两行是本机构造的物理状态对照。两杯均未放好和两杯互换盘子会产生完全相同的公开回执。公开回执足以告诉 27B 哪只杯子还需处理；具体错盘归因需要经过方向校准的图像复核，或在允许读取额外状态的实验中显式提供交叉支撑判定。[状态对照](../outputs/j-1795258253-584889/two-mug-audit/swap-control.json)

## 正常放第二只杯子需要多久

逐帧恢复同任务 50 条官方演示保存的场景 XML 和物理状态，共 12,909 帧，采样率 20 Hz。每条都先观测到白杯放对，随后两杯同时放对。首次 1/2 到首次 2/2 的仿真用时为 **5.45–8.90 秒，中位数 6.475 秒**。其中 22/50 条在首次 2/2 之前还曾从 1/2 回到 0/2。单次回退同样可能出现在正常操作中。[同任务官方演示数据](https://huggingface.co/datasets/yifengzhu-hf/LIBERO-datasets/blob/f13aa24a3da8c43c7225569f28c562979fa0e35a/libero_10/LIVING_ROOM_SCENE5_put_the_white_mug_on_the_left_plate_and_put_the_yellow_and_white_mug_on_the_right_plate_demo.hdf5)

| 候选复核规则 | 首次成功前会打断的演示 / 50 |
|---|---:|
| 首次看到仅一杯正确 | 50 |
| 同一项单独满足连续 2 秒 | 50 |
| 同一项单独满足连续 5 秒 | 50 |
| 只把 1/2 当进度，等待报完成、重复尝试或持续错盘的证据 | **0** |

最后一行采用因果回放，仅使用当时可见的数据。用两种来源的证据分别处理：

- **公开回执。** 第一次 1/2 只记录已完成的杯子。若 27B 此时报完成，可以把未满足项反馈给它。若持续缺同一项，且在首次看到 1/2 之后已观察到两轮完整的夹爪开、合、再开，第二轮松开后再等至少 0.5 秒仍未改善，才建议复核。条件变化或缺测会重置计数。开合是指令证据，无法直接证明抓住过杯子。只有等待、没有后续尝试或报完成的单杯停滞，这条规则会继续放行。
- **额外错盘检查。** 必须是同一只杯子、正确盘条件为假、错误盘支撑为真，且有打开夹爪的指令记录；跨至少两个不同采样点、间隔至少 0.5 秒，期间没有合爪指令。达到后仅请求一次复核。三条重建中这条规则带来 1 次新增覆盖。只用公开 1/2 分支则是 0/3。初态 2 的报完成已得到原生失败反馈；单凭该反馈无法指出杯子或盘位。

另以每 10、20、30 个 tick 采样一次模拟较稀疏的动作边界，新规则在每种粒度的 50 条演示中均为 0 次提醒。相应采样点捕捉到原生成功的条数分别为 50、49、49。正式终止应保留环境原生成功信号。50 条是演示者的成功轨迹，无法验证 27B 自身反复抓放后仍能成功的轨迹，也没有 27B 在本任务上真正卡在 1/2 的阳性样本。这次测得的是监督触发位置和误触发，未测干预后的成功率。

## 离线复现

仅从控制指令重建的三条失败轨迹没有历史物体位姿真值。初态向量逐条核对原记录 SHA-256；复用原始夹爪初始化、控制频率、逐 tick 的 OSC 绝对目标及夹爪指令，同时逐 tick 对比归档的末端位置。演示数据则直接恢复每一帧的物理状态。执行时间均用模拟器时钟。

仅复算触发统计使用 Python 标准库。完整重建另需对应的 LIBERO 工作树、OpenETA Benchmark 0.3.2、MuJoCo 2.3.7、robosuite 1.4.1、NumPy 1.23.5、SciPy 1.10.1，以及可在本机无渲染运行的 LIBERO 环境。输入包中保存已用的三个初态的控制档案、初态向量和 50 条演示的 XML／状态／动作；收集脚本也可直接读官方 HDF5。

```bash
D=outputs/j-1795258253-584889
python deploy/audit_mug_progress.py "$D/two-mug-audit"

# 在已配置 LIBERO 路径与依赖的本机环境中从输入重建
WORK=$(mktemp -d)
tar -xzf "$D/two-mug-audit/replay-inputs.tar.gz" -C "$WORK"
python deploy/collect_mug_receipts.py --libero-root "$LIBERO_ROOT" --output "$WORK/results" \
  archived "$WORK/archive" "$WORK/initial-states.npy" --events "$D/stall-audit/base-events.jsonl"
python deploy/collect_mug_receipts.py --libero-root "$LIBERO_ROOT" --output "$WORK/results" \
  demos "$WORK/demos"
python deploy/audit_mug_progress.py "$WORK/results"
```
